# Building and running Kinect4FOG

The release contains three deployable components.

## 1. Main Kinect4FOG application

### Requirements

- Windows.
- Microsoft Kinect v2 hardware and Windows support.
- Microsoft Kinect for Windows SDK v2.
- Visual Studio capable of building the .NET Framework target used by the project.
- Dependencies listed in `packages.config`.

### Build

1. Install the Kinect for Windows SDK v2.
2. Open `Kinect4FOG.sln`.
3. Restore required packages if Visual Studio requests them.
4. Build the solution.
5. Connect the Kinect v2 sensor before exercising sensor-dependent functionality.

Research data recordings are written to:

```text
Documents\Kinect4FOGData
```

No administrator permissions should be required for that data path.

## 2. Arduino laser controller

Location:

```text
Components/ArduinoController/
```

Open `Kinect4FOGArduino.ino` in the Arduino IDE.

The historical hardware configuration uses:

- vertical servo: digital pin **11**;
- horizontal servo: digital pin **12**;
- serial communication: **9600 baud**;
- 16×2 I²C LCD at address **0x27**.

Required Arduino libraries:

- `Wire`
- `LCD`
- `LiquidCrystal_I2C`
- `Servo`

The main application sends newline-terminated serial commands:

- `1<angle>` for the vertical servo;
- `2<angle>` for the horizontal servo.

See `Components/ArduinoController/README.md`.

## 3. Windows monitoring client

Location:

```text
Components/WindowsClient/
```

### Requirements

- Windows.
- .NET Framework 4.6.
- Visual Studio capable of building WPF/.NET Framework 4.6 projects.

The client does **not** require the Kinect SDK.

### Build

1. Open `Components/WindowsClient/Kinect4FOGClient.sln`.
2. Build and run the solution.
3. The client listens on UDP port **8082**.

### Configure the main application

In the main Kinect4FOG application:

1. Open **Tools → Broadcast**.
2. Enter the IP address of the machine running the Windows client.
3. Enter port **8082**.
4. Save the broadcast configuration.

The cleaned client decodes the JPEG frames generated by the main application. Non-image packets received on the monitoring port are displayed as textual monitoring data.

Commands from the client are sent to UDP port **8089** on the main application.

## Hardware validation

Static source and project-reference checks can be performed without hardware, but a formal release should still be exercised on:

- Windows with Kinect for Windows SDK v2;
- Microsoft Kinect v2 hardware;
- the Arduino and both servo motors for laser control;
- two networked Windows machines if remote monitoring is to be validated end-to-end.
